# 도형탐험대 기능명세서

## 1. 목적·구조·적용 기준

초등 3~4학년이 Java Swing 데스크톱 앱에서 도형을 순서대로 배우고, 학습 캘린더와 포인트 랭킹을 확인한다. 파스텔 색상과 도형 캐릭터를 사용한다.

**한 PC에서 UI·학습 처리·파일 입출력이 함께 실행된다. 모든 영구 데이터는 해당 PC의 TXT/CSV 파일로 관리한다.** 여러 학생이 각자의 로컬 계정으로 로그인하며 계정 없이는 학습할 수 없다. 랭킹은 같은 앱 데이터 폴더에 등록된 학생끼리 비교한다. DB 제품이나 서버 구축은 필요하지 않다.

최신 인터뷰가 과거 결정에 우선한다. 서버 계정, 여러 PC 자동 공유, 게스트 학습, 계정 연결·병합, 재연결 동기화 요구는 폐기한다. 인터넷 연결 여부와 관계없이 동일한 기능을 제공한다.

이 문서는 개발 명세다. 기존 Swing 로그인 코드는 입력 검증 등을 제공하는 데모이며 실제 파일 인증·학습 기능 구현 완료를 의미하지 않는다. 기존 [Figma UI](https://www.figma.com/design/NBHcvfXRioQPk9GvUz35eA)의 예시 수치와 이전 안내보다 본 문서가 우선한다.

‘확정’은 사용자 답변, ‘설계안’은 구현을 위한 제안, ‘미정’은 추후 결정 사항이다. 아래 예외·저장 세부 방식은 별도 확정 표시가 없으면 설계안이다.

## 4. 과정·상태·계산

### 초기 레벨

| 기본 순서안 | 도형 | 난이도 |
|---|---|---|
| 1 | 삼각형 | 미정 |
| 2 | 정사각형 | 미정 |
| 3 | 직사각형 | 미정 |
| 4 | 마름모 | 미정 |
| 5 | 사다리꼴 | 미정 |
| 6 | 평행사변형 | 미정 |
| 7 | 원 | 미정 |

7개 구성은 확정, 세부 순서는 기존 인터뷰에 제시한 기본안이다. 운영용 콘텐츠에는 난이도를 지정해야 하며, 미정 상태를 0P로 바꾸거나 임의 보상하지 않는다. 이후 레벨을 추가해도 기존 ID를 바꾸지 않는다.

### 학습 상태

로그인 → 가능한 레벨 선택 → 설명 확인 → 문제 풀이 → 3문제 모두 정답 → 파일 저장 → 완료 결과. 복습은 설명을 건너뛸 수 있다. 설명 확인·선택 답안·정답 누적 상태는 메모리에만 두고 중단하면 폐기한다. **완료된 최초 학습과 완료된 복습은 모두 영구 저장**한다. 중간 학습을 저장하지 않는다는 결정이 복습 완료 기록을 버린다는 뜻은 아니다.

### 포인트·날짜·랭킹

- 같은 레벨 최초 완료는 한 번, 복습은 여러 번 기록할 수 있다.
- 학습일은 완료 시각 기준이다. 설명을 보거나 문제 일부를 맞힌 날은 학습일이 아니다.
- 서로 다른 완료 날짜를 정렬하여 하루씩 이어지는 구간을 계산한다. 3일째 20P, 7일째 50P를 지급한다. 같은 날 반복 완료로 연속일은 늘지 않는다. 10일·14일째 반복 보상은 없다.
- 하루를 빠뜨리면 다음 학습일부터 새 구간이며 새로 3일/7일 보상 가능. 단순 중단으로 이미 받은 포인트를 회수하지 않는다.
- 누적 포인트 = 학생별 지급 기록 금액 합. 랭킹 순위 = 본인보다 포인트가 높은 학생 수 + 1. 동점 행의 표시 순서는 학생 ID로 안정화하는 설계안이며 순위는 같다.
- 현재 연속일은 오늘 기록이 있으면 오늘, 없고 어제 기록이 있으면 어제 기준, 둘 다 없으면 0으로 표시하는 설계안이다.

## 5. 파일 관리와 프로그램 책임

화면(Swing) → 학습·계정·보상 처리 → 파일 저장 모듈 → TXT/CSV. 모두 같은 프로그램 내 구성 요소다. 네트워크 API 호출·서버 토큰·DB 접속은 없다.

| 데이터 | 파일 제안 |
|---|---|
| 학생 계정·프로필 | students.csv |
| 난이도별 보상 | difficulties.csv |
| 레벨·설명 장면 | levels.csv, lesson_scenes.csv |
| 문제·보기 | questions.csv, answer_choices.csv |
| 완료 기록 | completions.csv |
| 연속 보상 규칙 | streak_rules.csv |
| 포인트 지급 기록 | point_entries.csv |
| 아이디 기억 등 PC 설정 | preferences.txt |

파일별 열·참조는 [ERD.md](erd/ERD.md)에 정의한다. 기본키·외래키·중복 제한은 Java 코드가 검사한다. 비밀번호는 원문 대신 salt·알고리즘·작업량 정보를 포함한 비밀번호 검증값으로 저장한다. 모든 파일이 로컬이므로 OS에서 파일을 직접 수정하는 사용자까지 앱 로그인만으로 막을 수는 없다.

**저장 설계안:** 하나의 완료 처리에 완료 행·최초 포인트·연속 포인트가 포함된다. 각 CSV를 제각각 덮어쓰지 않고 전체 변경 파일 세트를 새 저장 세대로 작성·검증한 뒤 활성 세대를 가리키는 TXT를 교체한다. 실패 시 이전 정상 세대를 유지한다. 앱 시작은 같은 세대의 파일만 읽는다. 원자적 교체 지원 여부와 강제 종료 복구는 실제 구현 환경에서 검증한다. 백업 파일을 복구에 사용할 수 있게 보존하되 자동 보존 개수·기간은 추후 결정한다.

긴 파일 입출력은 Swing 화면을 멈추지 않도록 작업 스레드에서 처리하고 화면 갱신은 EDT에서 수행한다. 저장 중 중복 클릭을 차단하고 성공 확인 전 결과 화면을 확정하지 않는다.
