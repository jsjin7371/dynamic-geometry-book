# 도형탐험대 개발 계획

## 1. 목적과 기준

초등 3~4학년이 도형 설명과 애니메이션을 보고 문제를 풀며 학습 기록을 확인하는 오프라인 Java Swing 데스크톱 앱을 만든다. 여러 학생이 한 PC에서 각자의 계정으로 이용하고, 데이터는 로컬 TXT/CSV에 저장한다. 서버와 DB는 사용하지 않는다.

- 기능과 정책의 기준: [기능명세서](기능명세서.md). 데이터 구조와 저장 계약: [ERD](ERD.md).
- 화면 구성의 기준: [디자인 참고 이미지](design/reference/). 이미지의 예시 데이터와 기능이 명세와 다르면 명세가 우선한다. 예를 들어 12단계, 회원가입, 배지, 일일 목표, 효과음 및 모션 설정은 확정 요구사항이 아니다.
- 이 문서는 개발 순서와 협업 규칙이다. 명세의 미정 항목을 확정하거나 구현 완료를 뜻하지 않는다.

## 2. 구조와 객체 설계

다음은 새 프로젝트의 목표 구조다. 패키지명과 빌드 도구는 프로젝트 초기 설정에서 팀이 통일한다.

```text
src/
  main/java/<기본패키지>/
    app/                 # 앱 시작, 의존성 연결, 화면 전환
    gui/
      common/            # 테마, 공통 컴포넌트와 화면 기반 클래스
      auth/ home/ level/ lesson/ ranking/ profile/
    domain/              # 학생, 레벨, 학습 세션, 완료, 보상 등
    application/         # 계정, 학습, 조회, 보상 유스케이스와 저장 인터페이스
    infrastructure/      # CSV/TXT, 파일 잠금, 비밀번호 검증 구현
  main/resources/        # 앱에 포함할 도형·애니메이션 및 초기 콘텐츠
  test/java/             # 단위·통합 테스트
```

의존 방향은 `gui → application → domain`이다. `infrastructure`는 application의 저장 인터페이스를 구현하며, `app`이 구현체를 연결한다. GUI는 CSV를 직접 다루거나 보상·잠금 규칙을 계산하지 않는다. 도메인과 서비스는 Swing에 의존하지 않는다. 현재 학생과 진행 중 답안은 메모리 세션에 두고 로그아웃·중단 시 폐기한다.

학생, 레벨, 문제, 학습 세션, 완료, 포인트 지급 기록을 각자의 불변 조건과 행위를 가진 객체로 설계한다. 계정 인증, 학습 시작·답안 제출·완료, 진도·랭킹 조회는 서비스의 공개 메서드로 제공한다. 저장 인터페이스는 테스트용 구현으로 교체할 수 있게 한다. 공통 책임이 명확한 경우 화면이나 컴포넌트의 부모 클래스를 만들어 상속하게 하되, 공통 스타일이나 독립 기능은 조합과 위임으로 공유한다. 업무 규칙을 거대한 부모 클래스나 정적 유틸리티에 몰아넣지 않는다.

## 3. 팀 공통 UI

참고 이미지의 1440×960 데스크톱 구성, 밝은 배경, 짙은 녹색 강조, 민트·노랑·보라 파스텔 카드, 둥근 모서리와 도형 캐릭터를 기준으로 한다. Noto Sans KR을 사용할 수 있으면 적용하고 대체 글꼴도 지정한다. 실제 창 크기 변화와 한글 텍스트 길이를 고려해 레이아웃을 구성한다.

- `gui/common`에 색상·글꼴·간격·모서리 등 테마와 버튼, 입력 필드, 카드, 상태 표시, 페이지 제목을 둔다. 팀원이 텍스트·상태·이벤트를 전달해 호출할 수 있는 생성 메서드 또는 컴포넌트로 제공한다.
- 로그인 이후 화면은 공통 헤더와 사이드바를 공유한다. `JFrame`과 `BorderLayout`, `CardLayout`을 사용해 로그인·나의 탐험·레벨 지도·학습·랭킹·프로필로 전환한다. 화면은 필요한 데이터를 서비스에서 받아 표시한다.
- 캘린더는 7열과 `LocalDate`, 랭킹은 표와 내 행 강조를 활용한다. 학습 장면은 `paintComponent`와 Swing `Timer`로 그리며 재생·일시정지·다시 보기와 자막을 제공한다. 화면 이탈 시 타이머를 정리한다.
- 공통 컴포넌트의 공개 사용법과 간단한 호출 예제를 코드와 함께 기록한다. 새 화면은 먼저 기존 컴포넌트를 사용하고, 공통으로 필요한 변경은 다른 화면의 호출과 상태를 함께 확인한다. 로딩·빈 목록·입력 오류·저장 실패 상태도 제공한다.

## 4. 단계별 구현

1. **기반과 공통 UI:** 빌드·실행·테스트 환경, 패키지, 앱 진입점과 화면 전환을 구성한다. 테마와 공통 컴포넌트를 만들고 로그인 및 나의 탐험 화면에서 재사용을 확인한다.
2. **저장과 계정:** ERD의 9개 CSV 및 설정 파일을 UTF-8로 읽고 쓴다. CSV 인용 규칙과 PK/FK/유일성·콘텐츠 제약을 검증하고, 최초 설치와 손상을 구분한다. 로컬 계정 인증, 아이디 기억, 비밀번호 변경과 로그아웃을 구현한다. 비밀번호는 원문이 아닌 salt·알고리즘·작업량이 포함된 검증값으로 저장한다.
3. **학습 흐름:** 활성 레벨과 선행 조건을 서비스에서도 검증한다. 최초 학습은 설명 확인 후 고정 객관식 세 문제를 풀고, 맞힌 문제는 현재 세션에 유지하며 오답만 재도전한다. 완료 레벨은 복습을 허용하고 설명을 생략할 수 있다. 중단 시 진행 중 상태를 버린다.
4. **완료와 보상:** 세 문제 정답 후 완료와 포인트를 한 저장 단위로 확정한다. 최초 보상은 학생·레벨당 한 번, 연속 3일과 7일 보상은 각 연속 구간에서 한 번 지급한다. 재시도에 같은 완료 ID와 ERD의 보상 키를 사용한다. 저장 성공 후에만 결과 화면을 표시한다.
5. **조회 화면:** 완료 기록과 포인트 기록에서 진도, 한국 날짜 기준 학습일과 연속일, 캘린더, 프로필, 전체 학생 랭킹을 계산한다. 동점은 공동 순위이며 다음 순위를 건너뛴다. 랭킹에는 닉네임·캐릭터·포인트만 표시한다.
6. **통합 검증:** 일곱 레벨의 콘텐츠와 애니메이션을 준비하고, 활성 레벨의 장면·문제·보기와 난이도 배정을 검증한다. 아래 인수 기준을 통과하고 실제 운영 환경에서 저장 복구를 확인한다.

저장 시 전체 데이터 세트를 새 세대에 작성·검증한 뒤 활성 세대 포인터를 교체하고 이전 정상 세대를 보존한다. 같은 데이터 폴더를 사용하는 앱 인스턴스는 쓰기 잠금을 공유한다. 손상된 파일을 빈 데이터로 덮어쓰지 않는다. 저장 실패와 재시도 방법을 안내하고, 강제 종료 및 포인터 교체의 원자성은 대상 OS에서 검증한다. 긴 파일 작업은 백그라운드 스레드에서, Swing 갱신은 EDT에서 수행한다.

## 5. 검증과 협업

- 단계 2: 로그인·학생 분리 및 CSV 특수문자와 무결성 오류를 검증한다. 기능명세서 AC-01~03, AC-18~19에 대응한다.
- 단계 3: 잠금, 설명 확인, 오답 재도전과 중단 후 상태 폐기를 검증한다. AC-04~07에 대응한다.
- 단계 4: 최초·복습 완료, 중복 클릭·재시도, 연속 보상과 저장 중단 복구를 검증한다. AC-08~14 및 AC-17에 대응한다.
- 단계 5: 동점 순위, PC별 랭킹 범위, 개인 기록과 날짜 경계를 검증한다. AC-11, AC-14~16에 대응한다.
- 서비스와 도메인 규칙은 단위 테스트하고, 임시 데이터 폴더에서 CSV와 세대 저장을 통합 테스트한다. 주요 화면은 공통 컴포넌트 재사용, 오류 상태, 화면 전환과 EDT 동작을 실행해 확인한다.
- 작업은 기능 단위 브랜치로 나누고 변경 목적, 실행 방법과 검증 결과를 리뷰에 남긴다. 공통 인터페이스나 컴포넌트 변경 시 기존 호출부와 관련 테스트를 함께 확인한다. 각 단계는 해당 기능의 동작·오류 처리·테스트가 끝나야 완료한다.

## 6. 결정 대기

- 일곱 레벨 각각의 난이도와 최종 학습 순서. 난이도 없는 레벨은 활성화하거나 임의의 0P 보상을 지급하지 않는다.
- 계정 생성·찾기·초기화 방식과 비밀번호 규칙, 백업 보존 기간, PC 시계 역행 처리 정책. 운영자 기능은 구현하지 않는다.
- 날짜 상세 조회와 프로필 편집 범위 등 명세에서 선택 또는 설계안으로 표시된 항목은 합의 후 범위를 확정한다.
