# 도형탐험대 개발 계획

## 1. 목적과 기준

초등 3~4학년이 도형 설명과 애니메이션을 보고 문제를 풀며 학습 기록을 확인하는 오프라인 Java Swing 데스크톱 앱을 만든다. 여러 학생이 한 PC에서 각자의 계정으로 이용하고, 데이터는 로컬 TXT/CSV에 저장한다. 서버와 DB는 사용하지 않는다.

- 기능과 정책의 기준: [기능명세서](기능명세서.md). 데이터 구조와 저장 계약: [ERD](ERD.md).
- 화면 구성의 기준: [디자인 참고 이미지](design/reference/). 이미지의 예시 데이터와 기능이 명세와 다르면 명세가 우선한다. 예를 들어 12단계, 회원가입, 배지, 일일 목표, 효과음 및 모션 설정은 확정 요구사항이 아니다.
- 이 문서는 개발 순서와 협업 규칙이다. 명세의 미정 항목을 확정하거나 구현 완료를 뜻하지 않는다.

## 2. 구조와 객체 설계

현재 프로젝트 구조다.

```text
src/
  main/java/geometrybook/
    app/                # 앱 시작, 화면 전환
    gui/
      common/           # 테마, 공통 컴포넌트
      auth/             # 로그인
      home/             # 나의 탐험
      level/            # 레벨 지도
      lesson/           # 세부페이지, 퀴즈패널
        animation/      # 도형별 애니메이션
      quiz/             # 퀴즈페이지
      wrongnote/        # 오답노트 (예정)
    domain/             # 레슨 내용, 학습 진도, 퀴즈 채점
      quiz/
    application/quiz/   # 퀴즈 문제 조회 인터페이스
    storage/            # CSV 읽기·쓰기, 계정, 비밀번호 해시
  test/java/geometrybook/   # 외부 라이브러리 없는 테스트
data/                   # CSV 파일
```

랭킹·프로필 화면(B안)과 앱에 포함할 이미지 폴더는 구현할 때 추가한다.

패키지 의존 방향은 다음과 같다.

```text
app → gui, domain, application, storage
gui → domain, application
application → domain
storage → (퀴즈 문제 읽기를 붙일 때) application, domain
```

- 화면은 CSV를 직접 다루지 않는다.
- 파일 입출력은 `storage`에서만 한다.
- `domain`과 `storage`는 Swing을 쓰지 않는다.
- 화면과 `storage`는 `app`에서 연결한다. 예를 들어 `AppNavigation`이 `AuthService`를 만들고, `LoginPanel`에는 로그인 동작만 넘긴다.
- 현재 학생과 진행 중 답안은 메모리에 두고 로그아웃·중단 시 폐기한다.

학생, 레벨, 문제, 학습 세션, 완료, 오답 기록을 각자의 불변 조건과 행위를 가진 객체로 설계한다. 퀴즈 문제 조회는 `QuizSource` 인터페이스로 분리해 임시 데이터와 CSV 구현을 바꿀 수 있게 한다. 공통 책임이 명확한 경우 화면이나 컴포넌트의 부모 클래스를 만들어 상속하게 하되, 공통 스타일이나 독립 기능은 조합과 위임으로 공유한다. 업무 규칙을 거대한 부모 클래스나 정적 유틸리티에 몰아넣지 않는다.

## 3. 팀 공통 UI

참고 이미지의 1440×960 데스크톱 구성, 밝은 배경, 짙은 녹색 강조, 민트·노랑·보라 파스텔 카드, 둥근 모서리와 도형 캐릭터를 기준으로 한다. Noto Sans KR을 사용할 수 있으면 적용하고, 없으면 기본 글꼴을 쓴다. 실제 창 크기 변화와 한글 텍스트 길이를 고려해 레이아웃을 구성한다.

- `gui/common`에 테마(`Theme`), 라벨·입력칸·버튼(`UiComponents`), 둥근 패널과 버튼(`RoundedPanel`, `RoundedButton`), 공통 틀(`AppShell`), 캐릭터(`TriangleCharacter`)를 둔다.
- 앱은 `JFrame` 하나를 사용한다. `Main`이 프레임을 만들고, `AppNavigation`이 `setContentPane`으로 로그인·나의 탐험·레벨 지도·학습·퀴즈페이지·오답노트를 전환한다. 창을 닫을 때 학습이나 퀴즈가 진행 중이면 확인 후 종료한다.
- 로그인 이후 화면은 `AppShell`의 헤더와 사이드바를 공유하고, `BorderLayout`을 기본으로 배치한다.
- 학습 장면은 `paintComponent`와 Swing `Timer`로 그리며 재생·일시정지·다시 보기와 자막을 제공한다. 화면 이탈 시 타이머를 정리한다.
- 공통 컴포넌트의 사용법은 코드 주석에 적는다. 새 화면은 먼저 기존 컴포넌트를 사용하고, 공통 코드를 바꾸면 다른 화면도 함께 확인한다.
- 파일을 읽는 화면은 로딩·빈 목록·입력 오류·저장 실패 상태를 제공한다.
- 달력, 랭킹, 프로필 화면은 B안이다. 이미 있는 메뉴와 달력 화면은 유지한다.

## 4. 단계별 구현

### A안

1. **기반과 공통 UI:** 실행·테스트 환경, 패키지, 앱 진입점과 화면 전환을 구성한다. 테마와 공통 컴포넌트를 만들고 로그인 및 나의 탐험 화면에서 재사용을 확인한다.
2. **저장과 계정:** CSV 인용 규칙을 처리하는 공통 코드와 `students.csv` 읽기·쓰기를 만든다. 최초 설치와 파일 손상을 구분한다. `AppNavigation`에서 `AuthService`를 연결해 로그인·로그아웃을 구현한다. 계정은 `students.csv`에 미리 넣어 두고, 비밀번호는 원문이 아닌 검증값으로 저장한다.
3. **학습 흐름:** 화면과 도메인에서 모두 선행 레벨을 검증한다. 최초 학습은 세부페이지에서 설명을 확인한 뒤 퀴즈패널의 고정 객관식 3문제를 풀고, 맞힌 문제는 유지하며 틀린 문제만 다시 푼다. 완료한 레벨은 복습할 수 있고 설명을 생략할 수 있다. 중단하면 진행 중 상태를 버린다.
4. **완료 저장:** `levels.csv`, `progress.csv`를 읽고 쓴다. 퀴즈패널 3문제를 모두 맞히면 레벨 완료를 저장하고, 저장 성공 후 결과 화면을 표시한다. 로그인 시 해당 학생의 진도를 불러온다.
5. **퀴즈페이지와 오답노트:** `questions.csv`, `answer_choices.csv`에서 문제를 읽어 `QuizSource`를 구현한다. 틀린 순간 `wrong_answers.csv`에 저장하고, 결과 화면이나 오답노트에서 다시 맞히면 삭제한다. 오답노트 화면을 만든다.
6. **통합 검증:** 일곱 레벨의 콘텐츠와 애니메이션을 준비하고 최종 순서를 정한다. 기능명세서의 A안 인수 기준을 통과하는지 확인한다.

저장할 때는 임시 파일에 먼저 쓴 뒤 원본과 교체하고, 실패하면 기존 파일을 유지한다. 같은 데이터 폴더의 쓰기는 잠금으로 한 번에 하나씩 처리한다. 손상된 파일을 빈 데이터로 덮어쓰지 않으며, 저장 실패와 재시도 방법을 안내한다. 긴 파일 작업은 백그라운드 스레드에서, Swing 갱신은 EDT에서 수행한다.

### B안 (시간이 나면 추가)

보상과 난이도, 랭킹, 프로필, 달력 파일 저장, 아이디 기억, 비밀번호 변경, 계정 생성, 약점 단원 추천, 별, 퀴즈페이지 문제 해설을 필요한 순서대로 추가한다. 세부 규칙은 기능명세서의 B안을 따른다.

## 5. 검증과 협업

- 단계 2: 로그인, 학생 분리, CSV 특수문자, 무결성 오류, 파일 손상을 검증한다. 기능명세서 AC-01~03, AC-18~20에 대응한다.
- 단계 3: 잠금, 설명 확인, 오답 재도전과 중단 후 상태 폐기를 검증한다. AC-04~07에 대응한다.
- 단계 4: 레벨 완료 저장, 복습, 중복 클릭·재시도, 저장 중단을 검증한다. AC-08~10, AC-17에 대응한다.
- 단계 5: 퀴즈페이지, 오답 저장·삭제, 오답노트를 검증한다. AC-21~26에 대응한다.
- 단계 6: A안 인수 기준 전체를 다시 확인한다. AC-03의 진도·오답 분리는 단계 4·5 구현 후 최종 확인한다.
- B안: AC-11~16은 해당 기능을 추가할 때 검증한다.
- 도메인과 저장 규칙은 외부 라이브러리 없는 테스트로 확인하고, CSV 저장은 임시 데이터 폴더에서 테스트한다. 주요 화면은 오류 상태, 화면 전환과 EDT 동작을 실행해 확인한다.
- 작업은 기능 단위 브랜치로 나누고 변경 목적, 실행 방법과 검증 결과를 리뷰에 남긴다. 공통 인터페이스나 컴포넌트 변경 시 기존 호출부와 관련 테스트를 함께 확인한다. 각 단계는 해당 기능의 동작·오류 처리·테스트가 끝나야 완료한다.

## 6. 결정 대기

- 일곱 레벨의 최종 순서: 세부페이지를 합칠 때 정한다.
- 레벨과 코드의 연결 방식: 지금은 `LevelMapPanel`, `QuizPanel`, `LessonTopic`이 순서로 짝을 맞춘다. 순서를 바꿔도 맞도록 레벨 ID로 연결할지 정한다.
- ERD의 `progress.lastSceneNo`, `question.reviewSceneNo`: A안 정책에서 쓰지 않는다. CSV 구현 전에 열을 뺄지 빈 값으로 둘지 정한다.
- 퀴즈페이지의 레벨당 문제 수와 작성 담당: 문제 작성 전에 정한다.
